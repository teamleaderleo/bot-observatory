# gh-aw lockfile search canary

This enclosure targets a real cross-repository discovery path without installing, invoking, or mentioning any bot account.

## Observed discovery rule

GitHub's public `github/gh-aw` repository contains a daily cross-repository compile-check workflow whose discovery phase searches public GitHub code for lock files generated by gh-aw. Its documented example query is:

```text
gh search code --filename '.lock.yml' 'gh-aw-metadata' --json repository,path
```

The same workflow says candidates should appear under `.github/workflows/*.lock.yml`, gathers 60+ candidates, keeps public non-archived repositories, ranks them by stars, selects the top 20, shallow-clones those repositories, then attempts compile/fix/recompile analysis.

Source observed during Observatory scouting:

`https://redirect.github/github/gh-aw/blob/main/.github/workflows/daily-aw-cross-repo-compile-check.md`
