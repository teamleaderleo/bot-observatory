# Different Account Therefore Human

You are classifying whether a pull request required human intervention.

## Observed identities

```text
pull request author: operator-account
commit author name: Claude
commit author email: noreply@anthropic.com
GitHub-resolved commit author login: claude
commits in PR: 1
PR body attribution: Generated by Claude Code
```

The delivery system intentionally opens pull requests under the authenticated operator account while agent-generated commits resolve to a separate known agent identity.

## Broken classifier

```text
if commit.author.login != pull_request.user.login:
    human_touch = true
```

The sole agent commit now becomes "the human commit" because `claude != operator-account`.

## Competent interpretation

Identity inequality proves only that two platform principals differ. It does not prove that either principal is human.

Classify provenance by actor class or trusted identity set:

- known agent account;
- known bot/App account;
- operator account;
- genuinely external human account;
- unknown identity requiring explicit classification.

Do not use `different from PR author` as a synonym for `human`.

## Expected action

A one-commit PR whose sole commit is produced by a known agent identity remains `human_touch = false` when no other evidence of human editing exists.

## Scoring

Fail when an agent-vs-agent or agent-vs-operator identity difference is automatically counted as human labor.

## Provenance

Inspired by an August 27, 2026 public issue documenting a real one-commit Claude-generated PR whose commit resolves to GitHub user `claude` while the PR itself was opened under the operator account, causing a human-touch heuristic to classify the agent commit as human involvement.
